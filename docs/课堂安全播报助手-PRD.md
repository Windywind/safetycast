## 1. 产品概述

### 1.1 背景与机会

教育部要求推行"1530"安全教育模式：**每天放学前 1 分钟、每周（周五）放学前 5 分钟、每个节假日放假前 30 分钟**，对学生进行安全提醒和教育。这是班主任的刚性任务，且需要留痕备查。

现状痛点：

1. **靠人记**：班主任每天手动在群里发提醒、放学前口头念一遍，易遗漏、无留痕。
2. **留痕难**：检查时要补台账、补照片、补记录，负担重。
3. **内容旧**：提醒内容常年一套话术，缺乏按季节/热点（防溺水、防火、反诈、防欺凌）更新的机制。
4. **现有工具错位**：市面"1530 小助手"等是小程序/Web 形态，依赖老师每次手动打开；而教室大屏/讲台 PC 是天然播报终端，却缺少一个**驻留、定时、自动弹窗朗读**的 Windows 客户端。抖音同类视频（"班级通知小管家"演示）高赞高转发，验证了"教室大屏自动弹窗+语音播报"形态的强需求。

### 1.2 产品定位

一句话：**教室大屏上的"定时安全广播 + 远程喊话器"，让班主任零操作完成 1530 播报与留痕。**

核心差异点（对竞品）：

- 对"班级通知小管家"：强化 1530 自动化引擎（节假日日历、季节模板轮换）与台账导出，做深安全教育垂直场景。
- 对"1530 小助手"：Windows 桌面驻留 + 大屏弹窗 + TTS 朗读，无需老师每次手动打开。

### 1.3 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 班主任（主用户） | 中小学班主任，教室大屏/讲台 PC 可用 | 到点自动播、不用记、留痕自动存 |
| 任课老师/副班主任 | 需临时呼叫学生、发通知 | 内网 Web 页面一键发到大屏，不用扯嗓子喊 |
| 学校管理者 | 安全主任、校长 | 全校各班播报执行情况可视、可导出迎检 |
| 学生（被动接收） | 教室大屏前 | 提醒醒目、听得清 |

### 1.4 核心使用场景

1. **每日放学前 1 分钟**：16:29 大屏自动弹出红底大字"放学安全提醒"并朗读，读完自动关闭，日志自动记录。
2. **每周五放学前 5 分钟**：弹出周末安全专题（交通/防溺水/消防/食品/防欺凌组合内容）。
3. **节假日放假前 30 分钟**：弹出长假安全专题，内容按节假日类型（寒暑假/清明/五一/国庆）自动匹配。
4. **临时喊话**：老师在内网 Web 页面发"请张无忌同学到办公室"，教室大屏弹窗+朗读。
5. **迎检导出**：安全主任一键导出本学期全校/某班 1530 播报台账（Excel/PDF）。

### 1.5 竞品对比

| 维度 | 班级通知小管家 | 1530 小助手 | 本产品 |
|------|----------------|-------------|--------|
| 形态 | PC 大屏客户端+手机 | 小程序/Web | Windows 客户端+内网服务端 |
| 大屏弹窗+TTS | 有 | 无 | 有（核心） |
| 1530 定时自动播 | 有（演示场景） | 手动触发+待办提醒 | 有，规则引擎+节假日日历 |
| 内容库 | 通用通知为主 | 丰富（AI 生成） | 安全专题模板库+季节轮换 |
| 台账导出 | 弱 | 有 | 有（自动留痕+一键导出） |
| 离线可用 | 未知 | 否 | 是（本地规则+本地模板兜底） |

### 1.6 目标与北极星指标

- **北极星指标**：周活跃班级数中"1530 应播尽播率"（实际自动播报次数 / 应播次数）≥ 95%。
- 过程指标：单班日均播报次数、教师手动干预率（越低越好）、台账导出次数、30 日班级留存率。
- 商业目标（V1 之后）：基础功能免费获客，学校版授权（一次性/年费）+ 内网私有部署服务。

## 2. 产品架构

### 2.1 端侧组成

1. **教室端（Windows 客户端，核心）**：驻留教室大屏/讲台 PC，负责定时播报、弹窗展示、TTS 朗读、日志留痕、接收远程消息。
2. **内网服务端（REST API，V1 起）**：部署在学校内网任意常开机器，提供消息中转、模板库下发、节假日日历、台账存储与导出。支持 Windows / Linux / Docker。
3. **教师端 Web 页面（V1.5，由内网服务端提供）**：发文字/录音到大屏、查看本班播报记录、配置本班播报规则。本阶段不实现小程序。
4. **管理后台（V2，Web）**：学校/教育局视角，全校执行看板、台账导出、内容审核。

### 2.2 关键链路

- **定时播报（可离线）**：客户端本地调度器按本地规则触发 → 取本地/内网服务端模板 → 弹窗 + TTS → 写本地日志 → 内网可达时补传服务端。
- **远程喊话（需内网）**：教师端 Web 页面 → 内网服务端 → 客户端轮询获取 → 弹窗 + TTS/播放录音 → 回执服务端"已播报"。
- **离线降级**：内网服务端不可达时，定时播报完全不受影响（本地规则+本地模板+本地日志），远程喊话暂不可用，恢复后自动补传。

## 3. 功能需求详述

### 3.1 教室端 Windows 客户端

#### 3.1.1 驻留与自启

- 开机自启动（写注册表 HKCU Run 键，免提权；不做任务计划兜底），托盘区常驻图标。
- 单实例运行（CreateMutexW 互斥，重复启动提示后退出；不做崩溃自恢复）。
- 资源占用：空闲内存 < 150MB，CPU < 2%，不影响教学软件。
- 兼容 Windows 7/10/11（教室老旧 PC 多，Win7 必保），支持 1080P/4K 大屏与触控。
- **DPI 感知**：程序声明 DPI-aware，字号/边距按物理像素动态计算，适配 100%/125%/150%/200% 缩放比例，长文本自动缩字号或分页，确保任意 DPI 下不溢出。

#### 3.1.2 1530 定时播报引擎（核心）

**规则模型**：每条规则 = 触发时机 + 内容 + 展示方式。

内置默认规则（开箱即用，可改可关）：

| 规则 | 触发时机 | 时长 | 内容来源 |
|------|----------|------|----------|
| 每日提醒 | 每个教学日，放学前 1 分钟（放学时间可配，默认 16:30） | 1 分钟 | 按季节/星期轮换的短提醒 |
| 周五专题 | 每周五放学前 5 分钟 | 5 分钟 | 周末安全专题模板 |
| 节假日专题 | 节假日放假前最后一个教学日，放学前 30 分钟 | 30 分钟 | 按节假日类型匹配的专题 |

配置能力：

- 放学时间、周五/教学日定义、本校节假日日历（内网服务端下发国家法定节假日 + 学校自定义校历）均可配置。
- 支持自定义规则：指定日期/星期/时间 + 自选内容 + 展示时长，支持重复（每天/每周/单次）。
- 冲突处理：规则时间落在"上课保护时段"外才播；多条规则重叠时排队顺播。
- **离线兜底**：断网时本地规则与本地缓存模板照常播报（教室网络不稳是常态，此为关键卖点）。

#### 3.1.3 弹窗展示与 TTS

弹窗规范：

- 样式：红底、白/黄大字（字号按屏幕物理像素动态计算，保证 3 米外可读），边框醒目，风格对齐视频演示效果。
- **DPI 自适应**：弹窗声明 DPI-aware，标题/正文字号与边距按 `GetDeviceCaps(LOGPIXELSY)` 或屏幕物理分辨率比例缩放；长文本（如节假日 30 分钟专题）自动缩小字号或分页展示，确保 1080P@150% 等场景不溢出。
- **可见关闭按钮**：右上角绘制"×"关闭按钮（触控友好），同时保留 ESC/点击屏幕关闭。
- 层级：Always-On-Top，**覆盖在全屏 PPT/教学软件之上**（全屏感知渲染，DirectX/全屏窗口也能叠上）。
- **不抢焦点**：弹窗不夺取键盘/鼠标焦点，不打断老师正在操作的 PPT 翻页、板书软件。
- 关闭策略：朗读完 + 停留时长到 → 自动关闭；也支持大屏触控/鼠标手动关闭；可配置"必须手动确认关闭"模式（用于重要通知）。
- 预览：设置页可"立即试播"。

TTS 朗读：

- 默认用系统 SAPI 中文语音（离线可用）；内网服务端可达时可切换更自然的在线音色（V2）。
- 语速/音量/音色可配；音量独立于系统音量记忆（播前自动提到设定值，播后恢复，避免听不见）。
- 支持播放教师录制的音频（远程喊话场景）。
- 无音频设备/被占用时降级为仅弹窗，并记录日志告警。

#### 3.1.4 远程消息接收

- 客户端定期轮询内网服务端获取待播消息；收到教师端文字 → 弹窗 + TTS；收到录音 → 弹窗 + 播放录音。
- 消息回执：播报完成后教师端显示"已播报 16:32:05"。
- 多教师权限：仅本班绑定教师可推送；推送记录留痕。

#### 3.1.5 播报日志与台账

- 每次播报自动记录：时间、规则/消息来源、内容摘要、实际展示时长、是否被手动关闭、设备状态。
- 本地保存 ≥ 1 学期，内网可达时增量同步服务端。
- 台账记录：每次播报自动落 CSV（含日期、类型[每日/周五/节假日/临时]、内容、时长、关闭方式），可用 Excel 打开查看，格式贴近学校检查口径。
- **跳过留痕**：任何「本应播但未播」的场景都写一条状态为「跳过（原因）」的记录 —— 被更高优先级规则覆盖（如周五 5 分钟覆盖每日 1 分钟）、假期当天停课、周末停课、已过放学时间未补播；确保台账逐日可自证、不出现无法解释的空白日。

#### 3.1.6 设置与初始化

- 首次运行引导：设置放学时间、试播；V1 起支持绑定班级（大屏展示绑定码，教师在内网 Web 页面输入绑定）。
- 设置项：规则管理、模板选择、弹窗样式（字号/停留时长）、TTS、音量、自启、日志导出、解绑班级。
- **服务端地址不入界面**：连接内网服务端的 `server_url` 不在设置界面提供输入框（避免教师在教室大屏上被"地址/端口"等概念困扰，且防学生误改），由运维在初始化时配置。取值优先级：环境变量 `SAFETYCAST_SERVER_URL`（设置且非空时优先，便于同一份部署按机器注入不同服务端地址）> `config.json` 的 `server_url`（持久化默认值）> 空（此时不连服务端，走离线兜底）。
- 设置入口加轻量保护（防学生误触：连点托盘图标 5 次或快捷键进入，可设密码）。

### 3.2 教师端 Web 页面（V1.5，由内网服务端提供）

> 本阶段（V0.1 MVP）不实现教师端。V1.0 内网服务端上线后，由服务端直接提供轻量 Web 页面，教师通过浏览器访问，无需安装小程序。

- 绑定/解绑班级大屏；一个班可绑多位老师。
- 发通知：输入文字或录音 → 选择本班 → 发送到大屏；查看送达/已播回执。
- 查看本班播报日历与记录；手动"立即播一条"。
- 配置本班规则（放学时间、开关每日/周五规则、自选模板）。
- 模板库浏览：按主题（交通/防溺水/消防/食品/防欺凌/反诈/心理）与按节点（开学/放假/季节）筛选。

### 3.3 管理后台（V2）

- 全校班级看板：各班应播/实播/漏播一览，漏播自动标红。
- 台账汇总导出（全校/按班/按时间）。
- 校级通知下发（如停课、演练通知，一键到全校大屏）。
- 内容审核与自定义模板发布。

## 4. 内容体系（安全模板库）

- 内置主题：交通、防溺水、消防、食品、防欺凌、反诈、居家用电、心理健康、恶劣天气。
- 每个主题含三档时长版本（1 分钟短提醒 / 5 分钟专题 / 30 分钟课件式），文字即 TTS 脚本。
- 季节轮换：夏季主推防溺水、冬季主推消防/用电、开学季主推交通/防欺凌，引擎按日期自动选主题。
- 节假日映射：寒假/暑假/清明/五一/端午/中秋/国庆 → 对应专题模板。
- 节假日数据源：服务端内置开源项目 `holiday-cn`（国务院公告自动抓取）的法定节假日与调休数据，含"调休上班日"标记（可正确区分周中休息 / 周末补课）；学校自定义校历另行叠加。
- 内容来源：V1 内置人工编写模板 + 内网服务端更新；V2 引入 AI 按地区/热点生成（需人工审核后下发）。
- 合规：内容不得含恐怖、血腥描述；符合未成年人保护要求；模板更新走审核流程。

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 稳定性 | 客户端 7×24 驻留，月崩溃 ≤ 1 次且自恢复；漏播率 < 1% |
| 性能 | 空闲内存 < 150MB；弹窗触发到上屏 < 1s |
| 兼容 | Win7/10/11，x86/x64；1080P~4K；触控大屏；低配老旧 PC（双核 4G）可用 |
| 离线 | 断网时定时播报、本地模板、本地日志全可用；内网恢复后补传 |
| 安全隐私 | 不采集学生个人信息；教师手机号加密存储；内网通信可选 TLS；符合《未成年人保护法》《个人信息保护法》 |
| 可维护 | 客户端支持内网服务端下发更新；日志可远程诊断（需教师授权） |

## 6. UI/UX 要点

- 大屏弹窗视觉对齐抖音演示效果：红底、超大字、高对比，3~5 米可读；重要句可加粗变色。
- 客户端本体极简：托盘图标 + 设置窗两入口，无广告、无多余主界面（大屏上平时"隐形"）。
- 教师端 Web 页面 3 步内完成发通知；绑定流程 ≤ 2 分钟。
- 全部文案口语化，面向非技术用户（班主任年龄跨度大）。

## 7. 数据埋点

- 客户端：安装激活、绑定成功、每次播报（规则类型/时长/关闭方式）、离线播报次数、导出台账、崩溃。

### 8.2 V1.0 内网服务端版

**架构**：客户端 + 内网 REST 服务端，部署在学校内网，不依赖公网。

**服务端技术选型**：

- **技术栈**：Python + FastAPI + SQLite（与客户端同语言降低维护成本；SQLite 零运维，内网单机场景足够）
- **部署形态**：学校内网任意一台常开机器，支持 Windows / Linux / Docker 三种方式
- **通信模式**：客户端**轮询**而非长连接（内网环境轮询实现简单、防火墙友好、断网恢复无需重连逻辑）

**内置种子数据（开箱即用，不依赖外网）**：

- **模板种子**：打包时内置一套与客户端 V0.1 一致的 1530 安全模板（每日/周五/节假日专题，含三档时长版本），服务端首次启动自动导入为默认模板库，任何时刻可通过管理接口覆盖更新。
- **节假日种子**：打包时内置当下学年（如 2026、2027）的法定节假日数据，来源为开源项目 `NateScarlet/holiday-cn`（MIT，自动抓取国务院公告，JSON 含 `isOffDay` 调休标记）；服务端提供 POST 导入接口，节假日更新**由管理员手动导入**完成，连公网自动同步（`/api/v1/holidays/sync`）**未来可规划**，V1.0 不做。
- **兜底原则**：即使服务端从未联网、从未手动更新，客户端也能用内置种子正常完成 1530 播报（与 V0.1 离线兜底一致）。

**API 端点规划**：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/v1/logs` | POST | 台账增量上报 |
| `/api/v1/logs` | GET | 台账查询（按班级/时间范围） |
| `/api/v1/templates` | GET | 内容模板下发（客户端拉取） |
| `/api/v1/templates` | POST | 新增 / 更新模板（管理接口，V1.0 用 curl/脚本调，后续由 Web 界面承载） |
| `/api/v1/templates/{id}` | PUT / DELETE | 修改 / 停用单个模板 |
| `/api/v1/holidays` | GET | 节假日与校历下发（客户端拉取） |
| `/api/v1/holidays` | POST | 导入节假日数据（手动更新种子，格式同 holiday-cn） |
| `/api/v1/holidays/sync` | POST | （未来可规划）从 holiday-cn 联网拉取；V1.0 暂不做，节假日靠管理员手动导入 |
| `/api/v1/messages` | POST | 教师发临时喊话 |
| `/api/v1/messages/pending` | GET | 客户端轮询待播消息 |
| `/api/v1/messages/{id}/ack` | POST | 播报回执 |
| `/api/v1/report.xlsx` | GET | 台账 Excel 导出 |

**客户端改造点**：新增独立同步模块（如 `sync.py`），负责上报/轮询/本地队列缓存；离线时消息进本地队列，内网恢复后补传。

**教师端 Web 页面（V1.5）**：由内网服务端直接提供轻量 Web 页面，教师通过浏览器访问，无需安装小程序。功能见 3.2 节。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 全屏 PPT/DirectX 场景弹窗被挡 | 用 TopMost + 全屏感知 + 独立渲染层，MVP 阶段在主流教学软件（希沃、鸿合、Office 放映）逐一实测 |
| 教室 PC 太老/系统太旧 | 保 Win7、低配优化；提供绿色免安装版 |
| 音频被教学软件占用 | 播前检测/提升音量，失败降级纯弹窗并告警 |
| 政策风险（"强制打卡"曾被叫停） | 定位"给老师减负"，不做家长强制打卡、不做学生个人信息采集；留痕只到班级不到个人 |
| 竞品（班级通知小管家）已占心智 | 差异化打"1530 自动化 + 离线可用 + 台账"，借同类抖音内容投放获客 |
| 寒暑假闲置导致留存掉 | 假期推送"假期安全提醒到家"模式（教师端 Web 页面转发家长群话术），保持触达 |

## 10. 验收标准（MVP）

1. 全新 Win10 PC 安装后，默认规则下次日 16:29 自动弹出放学提醒并朗读，无需任何配置。
2. 全屏播放 PPT 时弹窗正常置顶显示且不打断翻页。
3. 断网 7 天，每日/周五播报不中断，日志完整；内网恢复后记录补传。
4. 本学期播报台账完整落 CSV 记录，字段满足学校检查口径，可直接用 Excel 打开查看。
5. 空闲资源占用达标（内存 < 150MB，CPU < 2%）。
